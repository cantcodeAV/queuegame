📦 Level 1: What is the First-In, First-Out (FIFO) Rule?

A Queue is a linear data structure that restricts data access according to the First-In, First-Out (FIFO) principle. The element that enters the queue first is guaranteed to be the element removed first. Think of a conveyor belt at a shipping factory or a line of people buying movie tickets—the first package placed on the belt reaches the shipping truck first!

REAR (Ingestion / Enqueue)

New items are added to the back of the queue (REAR pointer). It takes O(1) constant time.

FRONT (Exit Bay / Dequeue)

Items are removed strictly from the front (FRONT pointer). Trying to remove items from the middle violates FIFO!

// JavaScript FIFO Implementation
class Queue {
  constructor() { this.items = []; }
  enqueue(item) { this.items.push(item); } // Add at Rear
  dequeue()      { return this.items.shift(); } // Remove at Front
  peek()         { return this.items[0]; } // Inspect Front
}

🎟️ Level 2: Queue Operations & Boundary Safety

In fixed-capacity queues (like arrays with fixed memory limits), operations must check boundary states to prevent crashes, buffer overflows, and memory leak vulnerabilities.

➕ Enqueue(item)

Inserts a new element at the REAR pointer. Fails if the queue is full.

Complexity: O(1)
🎟️ Dequeue()

Removes and returns the element at the FRONT pointer. Fails if empty.

Complexity: O(1)
🔍 Peek()

Inspects the FRONT element without mutating or removing it.

Complexity: O(1)
⚠️ Overflow Exception

Occurs when calling Enqueue() on a queue that has reached max capacity (size === capacity).

⚠️ Underflow Exception

Occurs when calling Dequeue() on an empty queue (size === 0).

🚦 Level 3: Queue Implementation Variants

Standard queues can be adapted to overcome array memory fragmentation or handle urgent priority scheduling.

🔄 1. Circular Queue (Ring Buffer)

In linear array queues, dequeuing leaves wasted empty slots at the front. A Circular Queue connects the last memory slot back to the first using modulo wrap-around arithmetic:

rear = (rear + 1) % Capacity;

🚨 2. Priority Queue

Elements carry a priority level. High-priority items (e.g. Ambulances or OS interrupts) jump ahead of lower-priority items, overriding standard FIFO arrival order!

  • Hospital ER Triage (Ambulances served before routine checkups)
  • CPU Task Interrupt Handling
  • Dijkstra's Shortest Path Algorithm (using Min-Heap)

🚂 Level 4: Double-Ended Queue (Deque)

A Deque (pronounced "deck") is a generalized linear data structure allowing element insertion and removal from BOTH the FRONT and REAR pointers in O(1) constant time.

1. addFirst(item)

Inserts element at FRONT (Left gate).

2. addLast(item)

Inserts element at REAR (Right gate).

3. removeFirst()

Unlinks element from FRONT pointer.

4. removeLast()

Unlinks element from REAR pointer.

Versatility: Queue + Stack Hybrid

Because Deques allow operation at both ends, they can function as a FIFO Queue (insert Rear, remove Front) or a LIFO Stack (insert Front, remove Front). Common in text editor Undo/Redo buffers and Sliding Window Maximum algorithms.

🥞 Level 1: What is a Stack & the LIFO Principle?

A Stack is a linear data structure that follows the LIFO (Last-In-First-Out) principle. It contains only one pointer, TOP, pointing to the topmost element. Whenever an element is added, it is pushed onto the top of the stack, and only the top element can be removed or peeked.

➕ PUSH(x)

Inserts a new element onto the top of the stack.

Complexity: O(1) Constant Time
🗑️ POP()

Removes and returns the topmost element from the stack.

Complexity: O(1) Constant Time
🔍 PEEK()

Retrieves the topmost element without removing it.

Complexity: O(1) Constant Time
⚠️ Stack Overflow

Occurs when calling push() on a fixed-capacity stack that is already full (top == N - 1).

⚠️ Stack Underflow

Occurs when calling pop() on an empty stack (top == -1).

// C Array Implementation
void push(int x) {
    if (top >= n - 1) printf("Stack Overflow\n");
    else stack[++top] = x;
}
int pop() {
    if (top <= -1) { printf("Stack Underflow\n"); return -1; }
    return stack[top--];
}

🧪 Level 2: Expression Evaluation & Polish Notations

In human arithmetic (Infix), operators appear between operands (e.g., A + B * C) and require precedence rules and parentheses. Compilers convert these into Postfix (Reverse Polish) notation where operators follow their operands (e.g., A B C * +), enabling unambiguous linear-time evaluation using a single stack.

Infix Notation

Operator is between operands. Easy for humans, requires parentheses.

Example: A + B
Postfix Notation

Operator comes after operands. Evaluated with an operand stack.

Example: A B +
Prefix (Polish)

Operator comes before operands. Scanned from right to left.

Example: + A B
Postfix Evaluation Algorithm:
  1. Scan expression tokens from left to right.
  2. If an operand (number) is encountered, push it onto the stack.
  3. If an operator is encountered, pop two operands from the stack: A (top) and B (second).
  4. Evaluate B op A and push the computed result back onto the stack.
  5. When the expression ends, the sole remaining element in the stack is the final answer!

🛡️ Level 3: Syntax Sentinel (Checking Correctness of Parentheses)

Balanced parentheses refer to an expression in which all opening and closing brackets (), {}, [] are properly matched and nested. A balanced expression ensures code can be compiled without syntax errors.

How the Algorithm Works:
  • Iterate through the string character by character.
  • When an opening bracket (, {, [ is encountered: push it onto the stack.
  • When a closing bracket ), }, ] is encountered:
    • If the stack is empty ➔ Unbalanced (closing bracket without opener).
    • Compare with the top element of the stack. If they form a matching pair, pop the top element!
    • If they do not match ➔ Unbalanced (bracket type mismatch).
  • At the end of traversal, if the stack is completely empty, the expression is Balanced! If elements remain, it is Unbalanced.

🔭 Level 4: Monotonic Stack (Next & Previous Greater Element)

Next Greater Element (NGE): For an element x in an array, find the first element to its right that is strictly greater than x. If none exists, its NGE is -1.
Previous Greater Element (PGE): The first element to its left that is strictly greater than x. If none exists, its PGE is -1.

Why Use a Monotonic Stack?

A naive approach requires nested loops taking O(N²) quadratic time. By maintaining elements in monotonic order, each element is pushed and popped at most once, reducing runtime to O(N) linear time!

Worked Example

For array [1, 3, 2, 4]:
• NGE for 1 is 3
• NGE for 3 is 4
• NGE for 2 is 4
• NGE for 4 is -1
Result: [3, 4, 4, -1]

🔄 Level 5: String Reversal & Radix Base Conversion

The inherent LIFO property makes Stacks the ideal data structure for operations that require reverse output.

1. String Reversal

Push all characters of a string into the stack one by one. Then pop every character out from the stack. The characters emerge in exact reverse order (e.g., "STACK" ➔ "KCATS").

2. Decimal Number Base Conversion

To convert a decimal integer to Binary, Octal, or Hexadecimal, repeatedly divide by the base and push the remainder into the stack. When the number reaches 0, popping the stack yields the converted number digits from most to least significant!

🔗 Level 6: Dynamic Linked List Stacks & Call Stack Recursion

Exploring dynamic memory allocation on the heap and how operating systems execute recursive functions.

Linked List Implementation

Instead of using a fixed array, linked lists allocate memory dynamically on the heap. Each node has two parts: info (user data) and next (pointer to successor node). Pushing creates a node and sets newNode->next = top; top = newNode;. Popping updates top = top->next;.

No fixed capacity overflow limit!
Recursion & The Call Stack

When a function calls itself repeatedly, it uses the system Call Stack. Each invocation pushes a stack frame with local variables. When the base condition is reached, the stack frames pop in reverse order, unwinding and returning results up the call chain.

Example: factorial(4) unwinding
